# 培训即组织设计

> 培训模块不是课程系统，而是把「真实工作」变成「培养过程」的组织操作系统，其顶层是一张 C-level 画像地图：以画像定义高管岗位，以路径定义晋升阶梯，以真实业务为教材完成从执行到 C level 的角色跃迁。本洞察基于培训案例（案例集 training 目录）、培训核心思想（手册 training 章节）与培养路线决策整理。

## 一句话核心

**人事云培训模块的本质，是把 CEO 的培养心智产品化为系统规则，并把组织的高管分工编码为可执行的培养路线。** 案例中靠个人习惯完成的管理动作——渐进式授权、四问汇报、复述纪律、手册沉淀——全部变成可运行、可强制、可复盘的制度；画像化的 C-level 路线把「谁适合往哪里培养」从人治判断变成岗位能力模型。

## C-level 画像体系

培养对象以画像定义，不对应具体人员。职务设置参照腾讯已设立的高管职务及其分工，画像覆盖组织运转的完整能力轴：

| 画像 | 侧重 | 晋升路径 |
|---|---|---|
| CIO 首席信息官 | 维护现有大型系统 | CTO 助理 → 副秘书长 → 副总裁 → C level |
| 首席探索官（CXO） | 发展新功能新方法 | CTO 助理 → 副秘书长 → 副总裁 → C level |
| 首席产品官（CPO） | 产品体系与人类对接，产品策划、运营，产生商业价值 | CEO 助理 → 副秘书长 → 产品副总裁 → CPO |
| 首席市场官（CMO） | 变现 | 另行定义 |

守成（CIO）、探索（CXO）、产品（CPO）、变现（CMO）四项正交：互不重叠、互补成组织能力全图，是「正交分解」思想在高管层级的映射。

### 画像而非人名

- 能力标准前置：画像即岗位能力契约，不随人员变动而失效；
- 可竞争可轮换：画像不绑定具体人，延续赛马文化，谁达标谁上；
- 脱敏去人治：管理记录不留个人烙印，晋升评审有据可依。

## 晋升路径：角色跃迁的阶梯

两条路径本质相同，都是「助理 → 副秘书长 → 副总裁 → C level」的跃迁，只是入口不同：技术线（CIO/CXO）从 CTO 助理起步，贴着系统与创新；产品线（CPO）从 CEO 助理起步、经产品副总裁，贴着商业与用户。

每一级对应培训手册的三阶段论：助理重执行与思考习惯，副秘书长重组织协调，副总裁重经营决策，C level 重机制建设与带人。「从自己干到会教别人干」是每一级晋升的验收标准。

## 培养方法论：六大原则

1. **以真实业务为教材**——任务自带压力与反馈，被拒绝的客户、返工的报价是最好的教案；
2. **授之以渔**——先给框架与提问，不给结论；
3. **渐进式授权**——示范 → 尝试 → 接手 → 独立，管理者兜底；
4. **AI 是思考的脚手架**——「不要发 AI 原文，说你自己复述的结果」；
5. **培养的终点是教别人干**——个人经验沉淀为手册、清单、制度；
6. **按阶段一人一策**——新人重思考、骨干重经营、高管重机制，节奏不可颠倒。

## 从案例事实到产品需求

| 案例事实 | 推导出的需求 | 产品能力 |
|---|---|---|
| 商务经理培养周期长，「一步一步来」 | 长期一人一档，而非一次性课程记录 | 培养档案（一人一策） |
| 客户建档：范例 → 自己的想法 → 接手 | 任务级阶段状态机，每步有观察点与验收 | 带教协作（渐进式授权） |
| 报价三段式、预算三步法、四问框架 | 思维框架沉淀，按场景推送 | 框架库（授之以渔） |
| 「不要发 AI 原文，说你自己复述的结果」 | 复述纪律系统化，防止人变成转述工具 | AI 教练（AI 是脚手架） |
| 「没有交接文档，一律不算有效工时」 | 经验制度化闭环，不随人员流失 | 案例库与复盘（教别人干） |
| 试用期主线任务「兼具学习功能」 | 真实业务任务 = 学习项目 | 真实任务学堂（以业务为教材） |

## 六大能力模块

1. **培养档案（一人一策）**：阶段诊断 → 单重点培养目标 → 方法匹配 → 周期复盘，产出个人成长档案；C-level 画像作为档案的目标终点。
2. **真实任务学堂（以业务为教材）**：主线任务设计器，注明学习意图，真实交付 + 管理者兜底 + 事后复盘。
3. **框架库（授之以渔）**：思维框架沉淀与场景化推送，提交前用框架自检。
4. **带教协作（渐进式授权 + 教别人干）**：任务四步状态机 + 师徒关系 + 晋升带教义务。
5. **AI 教练（AI 脚手架）**：模拟客户/上级的陪练；复述检测（相似度过高直接打回）；产出质量与基准对照。
6. **案例库与复盘（经验制度化）**：脱敏案例沉淀、案例讨论会、四问复盘模板、从复盘生成手册草稿。

## 深层洞察

### 培训是筛选的延续

试用期主线任务本质上是筛选博弈的延续：管理者先设机制，员工通过行动暴露类型——「让他在试用期执行他的思路，看一看效果」。培训系统把「先筛选、后引导」制度化：主线任务既是培养，也是考察。

### 衡量单位的转变

通用 LMS 记「学了多少课、考了多少分」；本设计记「能独立做什么、能教别人什么」。衡量单位变了，系统设计就全变了——课程、证书不再是核心对象，任务、带教、复盘才是。

### 复述纪律是 AI 时代的制度创新

「不要发 AI 原文」从一句口头要求，变成系统强制规则（相似度检测打回）。这不是禁止 AI，而是强制消化：AI 可以梳理，但结论必须经过自己的判断与复述。这是 AI 原生组织把「人不能变成转述工具」产品化的尝试。

### 画像体系是高管梯队的产品化

从「创始人肉眼识人带人」到「画像 + 路径 + 评审」：画像定义验收标准，路径定义晋升阶梯，评审按章程执行。这与招聘考核课题评审章程的双轴评审（方向偏好轴 + 陈述质量轴）同构——判断课题是否值得做按章程执行，判断谁能晋升按画像评审。培养不再依赖个别人的眼光。

### 经验制度化的闭环

真实任务 → 复盘 → 手册 → 制度 → 新任务。个人经验一旦进入闭环，就不随人员流动流失（呼应「没有交接文档不算有效工时」）。培养的终点是组织能力，不是个人能力。

### 与「定价即组织设计」的呼应

薪酬洞察回答「用什么价格信号定义关系」，培训洞察回答「用什么培养机制定义成长」。两者共同指向意图仓库的核心问题：**如何用制度设计代替管理者直觉。**

- 薪酬：用外部渠道价格作锚点，利益结构代替管理者推动人；
- 培训：用状态机、观察点、复述纪律、画像路径，把管理者的培养动作变成系统默认。

## 落地顺序

1. **MVP**：培养档案 + 主线任务 + 四问周报（含 AI 复述检测）——只覆盖新人试用期，案例里最痛、闭环最短的场景；
2. **二期**：带教协作状态机 + 框架库；
3. **三期**：案例库 + 手册/制度沉淀 + 管理者培养仪表盘 + C-level 画像评审看板。

> 判断标准始终只有一个：**员工在这里不是在「上课」，而是在做真事、被带教、被复盘。**
